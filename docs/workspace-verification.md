# 0.4.0 实际账号工作台验收

验证日期：2026-10-20。环境为 Windows Docker Desktop、Linux Python3.12、MySQL8.4、Redis7.4、Celery/Dispatcher。所有验收账号与 PDF 均为构造测试数据；未使用用户的业务文件，不代表已在企业生产使用。

## 自动与集成验收

- 25 项自动测试通过，覆盖原有文档工程、人工闭环、隔离演示，以及新增真实会话身份、同源写入、会话撤销/过期、错误不回显密钥、跨项目隔离、最新草稿与冻结基线分开、项目创建幂等。
- MySQL Alembic 从0003升级到0004；模型检查无待生成迁移。
- 真实 HTTP 使用三份独立 Cookie 会话登录，未在业务调用中发送 API Key。文件上传通过 MySQL/outbox → Redis/Celery 实际解析。
- 四路并发登记同一问题仍只生成一条问题和任务；修改响应修订为2、发布新材料、负责人提交、另一账号复核、最终确认后报告完成。
- 再发布材料快照，完成状态失效、覆盖归零、旧任务显示 NEEDS_RECHECK；旧记录保留。
- 带会话下载 Markdown 报告成功；退出三个会话后访问受保护接口返回401。

## 浏览器验收

在本地工作台用专门构造测试账号完成：

1. 登录、创建空项目、通过网页文件选择器分别上传招标/响应 PDF；后台解析为3页、21处文字。
2. 选择招标第二页原文，录入要求并确认，发布要求基线。
3. 显式选择响应文件修订与正式用途，发布材料集。
4. 勾选响应第二页证据、填写人工意见，报告显示1/1；实际点击下载 Markdown 成功。
5. 登记补充说明问题并指派自己，开始整改，引用当前正式原文提交说明；页面提示提交人不能自审。
6. 负责人按姓名查找另一个测试账号并加入审查角色，退出后以该账号登录、查看并验收整改；回到审查页重新逐项确认。

实际浏览器窄屏宽度439px，报告页内容宽度同为439px，无整页横向溢出。保留了人工报告和页面截图供本轮交付查看。浏览器验收的是构造的“补充说明”任务；文件从4小时改为2小时并触发失效的路径由真实 MySQL 集成验收覆盖。

## 复现

```powershell
docker compose up --build -d --wait --wait-timeout 180
docker compose exec -T api python -m pytest -q
docker compose exec -T api python -m alembic check
docker compose exec -T api python scripts/business_smoke.py --base-url http://localhost:8000 --browser-session
```

自动测试使用临时 SQLite；集成脚本明确断言 MySQL。脚本每次保留一个新建构造项目，最后刻意置为需重新核对，随机账号密钥不输出、不写报告。默认不提交运行 JSON、原件、会话或本地环境文件。

## 不能据此推断的能力

未测高可用、负载、灾难恢复或企业生产环境。当前无模型抽取、RAG、自动审查、OCR或 DOCX；有文字层的 PDF 也需要人工回看原件，尤其复杂表格。会话登录仅是本地协作入口，正式共享环境仍需 HTTPS、组织身份、配额及完整密钥生命周期管理。
