# 0.6.0 要求候选抽取验收

验收日期：2026-10-21。环境：本地 Windows + Docker Desktop Linux 容器、Python3.12、MySQL8.4、Redis7.4、Celery。结果只适用于当前本地构造数据和测试范围。

## 完成的功能

可配置 Chat Completions HTTP 服务，默认严格 JSON Schema；选择已人工核对的最新招标/更正页，异步分批抽取并保存检查点；本地校验模型结构和引用；支持限流恢复、手工重试、取消和输入过期；人编辑后采纳为 DRAFT，继续原有确认/基线流程。网页展示模型及原文目的地，无配置时禁用生成，不提供伪装的默认候选。

本轮没有配置真实云模型密钥，没有真实模型推理、准确率、召回率或企业上线结论。

## 真实数据库和队列 + 合成 HTTP 契约

显式使用 `evaluation/extraction-fixture.compose.yaml`，运行 `scripts/extraction_smoke.py`。服务名、模型名和候选理由均标识合成验收，服务不会执行真实推理；仅 Compose 内网开放，不绑定宿主端口。

| 验收内容 | 实际结果 |
|---|---|
| 传入构造招标 PDF | 真实 HTTP → MySQL/outbox → Redis → 解析 Worker，生成产物 |
| 首次模型响应429 | 自动恢复，第2次执行成功 |
| 4路相同幂等键同时发起 | 只有1个抽取业务任务 |
| 完成批次 | 1/1，返回2条合成候选 |
| 4路相同幂等键同时采纳 | 只创建1条逻辑要求 |
| 采纳状态 | DRAFT，未确认，未自动发布基线，epoch保持0 |
| 追加选页质量意见 | 未处理候选标记过期，直接采纳返回409 |

脚本在运行前核对模型名，拒绝对实际云模型执行这一合成验收。构造测试账号不输出密钥，独立测试项目保留在本地库中，原件和数据库不进入 Git。

## 浏览器验收

使用本地 `/workspace` 的“工作台验收账号”和“个人项目验收 · 构造 PDF”，没有上传私人材料。实际操作：

1. 进入“AI 要求候选”，未核对页的勾选框禁用；显示 `synthetic-contract-fixture` 和内网目的地。
2. 在“解析质量”对构造招标第2页追加可用意见，回到候选页后只有第2页可选。
3. 明确勾选页码和发送确认，创建任务；网页轮询直到显示已完成1/1批、第2次执行及2条候选。
4. 编辑响应时限候选标题和正文，填写构造验收说明后采纳。原建议不覆盖，候选显示“已采纳为草稿”。
5. 立即切换“整理要求”，看到“服务响应时限 · 人工核对草稿 / 待确认”和原文出处；基线保持第1版，提示有未发布变化，发布按钮因存在草稿禁用。
6. 验收过程中发现并修复了工作台取最近任务未区分 kind 的关联错误，再次读取确认原文选择入口正常。
7. 停止并移除合成服务，正常 Compose 启动后网页显示未配置模型、生成按钮禁用；历史候选仍明确保留合成标识。最后退出验收账号，保留登录入口给使用者。
