# 1.0完整启动与运维

本文步骤交由用户执行。本轮按用户要求没有启动Docker、执行新功能测试或产生新浏览器截图。先在本地或隔离环境验收，再决定部署目标。

## 启动

在仓库根目录打开终端，启动Docker Desktop后执行：

```powershell
python scripts/init_env.py
docker compose build
docker compose up -d
docker compose ps -a
```

已有.env不会覆盖。升级已有0.8安装前先做数据库和documents卷的现有备份/快照；旧库不能使用新的备份工具强行跳过版本要求。不要执行 `docker compose down -v`，它会删除持久卷。

`migrate` 升级到0008，`bootstrap`准备初始用户；它们和`semantic-download`成功退出是正常状态。其他服务应持续运行：api、worker(parse)、converter-worker(convert)、retrieval-worker(retrieve)、extraction-worker(extract)、dispatcher、mysql、redis、milvus、semantic。首次下载固定语义权重约320MB，OCR另需模型；无外网可按manifest在可联网环境准备后拷入semantic_models卷。下载器验证摘要，不会自动换其他版本。

Compose初始化使用`--preserve-existing-name`：账号轮换密钥或停用后，重启不会把旧.env密钥重新建为同名初始账号，也不会重新启用账号。轮换后使用已保存的新密钥登录，并在受保护配置中更新评测工具所用账号密钥；不能再用旧.env值登录原账号。

保守准备Docker内存8GB以上、空闲磁盘15GB以上作为初始开发建议，尚未压测；解析器、数据库与重排并行时应以实际内存/磁盘观察调整。只有API绑定127.0.0.1:18080，其余服务不开放宿主机端口。

查看启动错误：

```powershell
docker compose logs --tail 100 migrate semantic-download semantic
docker compose logs --tail 100 converter-worker worker retrieval-worker extraction-worker dispatcher
```

日志可能包含环境与业务信息，分享前自行脱敏；不要发.env。连接失败检查服务状态，语义模型失败不自动降级。若明确需要纯关键词模式，在.env设置`BID_SEMANTIC_ENABLED=false`并重建API/相关worker；使用独立旧profile重建索引，不能拿原混合索引当作关键词索引。

## 配置云模型

在本地.env填写真实供应商配置，不在聊天中发送密钥：

```dotenv
BID_LLM_ENABLED=true
BID_LLM_BASE_URL=https://your-provider.example/v1
BID_LLM_MODEL=your-model
BID_LLM_API_KEY=your-local-secret
BID_LLM_OUTPUT_MODE=json_schema
BID_LLM_TOKEN_PARAMETER=max_completion_tokens
```

接口使用Chat Completions，必须支持JSON结构化输出；只支持json_object或max_tokens的供应商可明确修改对应变量。默认HTTPS，不允许携带URL凭据/查询参数，超时与输出上限有边界。未确认兼容性时不发送业务保密文件，先使用明确许可的构造样例。

```powershell
docker compose up -d --force-recreate api extraction-worker
```

页面“配置完整”仅检查变量，不证明网络或模型可用。发起候选/辅助任务前显示目的地并逐次勾选许可。API与extract worker读取云密钥；解析、转换、语义及检索worker不接收云密钥。

|步骤|操作|预期|
|---|---|---|
|资料|上传中文文字PDF、扫描PDF、含中文表格DOCX|保留原件，转换和解析各有状态；打开生成PDF检查字体/分页/页码，质量页逐页核对|

|辅助|配置实际模型，发送构造问题/要求|显示目的地与许可，结果引用存在，证据不足明确提示；采纳前可人工修改|
|整改|新增第二个账号、指派、提交、独立复核|提交者不能复核自己；换材料后旧提交过期，验收后仍须最终人工判断|

账号创建命令以`docker compose exec api python -m app.cli --help`和相应子命令帮助为准；用户密钥由受保护环境变量或CLI工具提供，不要写入公开脚本。管理员停用：`docker compose exec api python -m app.cli set-user-status 用户ID --disabled true`，会撤销会话。

## 构造评测（可选，实际写入三个项目）

准备好所有worker、模型服务与数据库后，由用户明确运行：

```powershell
docker compose exec api python -m scripts.evaluate_retrieval --create-synthetic-projects --url http://api:8000 --output /data/blobs/evaluation/retrieval-results.json
```

创建三个构造DOCX模板，实际经历转换/解析/发布/索引/查询，9问输出宏平均Recall@5、MRR@5和含重排HTTP耗时，明细含来源。不会调用云模型；失败会停止，不编造分数。结果位于documents卷，受保护保存，不提交运行数据。小语料不能代表长标书、跨页表格或生产准确率；还需以经许可的真实材料扩充人工标注，单独核对候选遗漏、条件保留、模型错误与采纳率。

## 备份与隔离恢复

工具面向完整安装，包含SQL逻辑行、原PDF、解析JSON、源DOCX及转换检查点；会话排除，认证摘要仍属敏感数据。Milvus与模型权重不备份。先停止dispatcher和worker，确保文档不再产生新写入；API维护期间避免用户操作，外部通过维护窗口或代理限制写入。本机单人环境可先停止API，再用一次性容器读取数据库。

```powershell
docker compose stop dispatcher worker converter-worker retrieval-worker extraction-worker api
docker compose run --rm api python -m scripts.backup_project --output /data/blobs/backups/release-1.zip
docker compose run --rm api python -m scripts.backup_project --verify /data/blobs/backups/release-1.zip
docker compose up -d
```

备份文件不得与其他用户共享下载，不要放入公开仓库。将ZIP复制到受保护、加密、异机存储；摘要核验不是恢复演练。重复文件名拒绝覆盖，每轮选新名称。

恢复必须先自行建立**隔离且为空的数据库**和**新的空文件目录/卷**，使用相同版本工具。在受保护环境变量`BID_RESTORE_DATABASE_URL`设置目标连接，用`--target-env`指定变量名，不把URL写在命令参数或文档里：

```text
python -m scripts.backup_project --restore /protected/release-1.zip --target-env BID_RESTORE_DATABASE_URL --blob-root /new-empty-volume
```

容器执行时用受保护env文件注入目标变量，并将新的卷挂到明确路径。工具拒绝与当前连接相同或非空数据库/目录；它不会修改当前服务连接。恢复后先配置隔离服务指向新DB和新卷，确认数据/原件一致、会话已撤销，再显式重建当前材料索引。不要启动旧安装和恢复安装共同消费同一Redis队列；使用独立Redis。未经恢复演练不承诺RPO/RTO，切换生产连接属于单独部署步骤。

## 指标与清理

负责人从“运行维护”查看逻辑修订总量、任务计数、历史索引/片段和受保护metrics；不是磁盘真实容量、吞吐或可用率。宿主卷的实际磁盘、容器内存和告警需要部署侧采集。当前只提供计数与健康检查，未配置外部监控告警平台。

```powershell
docker compose exec api python -m scripts.prune_retrieval --project-id 项目ID --older-than-days 30
```

默认dry-run，只选非当前材料且无活动任务的旧索引；核对数量后明确增加`--apply`删除其Milvus投影，MySQL历史仍保留。当前材料中的失败generation不在此清理范围。清理不是删项目/原件，仍需维护源数据的保留策略。
