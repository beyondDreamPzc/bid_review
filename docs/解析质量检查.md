# 解析质量检查：先确认系统读到了什么

适用版本：0.5.0。进入真实项目工作台，在导航点击“解析质量”，或在具体文件版本下点击“检查解析质量”。

## 对应的业务问题

招标原件可能包含扫描页、图片中的文字、复杂表格和多栏内容。“解析完成”只表示后台任务执行成功；如果系统没有读出关键要求，后续人工整理或 AI 检索都会缺少依据。

本板块让使用者看到每页实际提取的文字、程序提示和人工核对意见。它不重新解析，不改写原文、不重编号已有引用，也不把“没有警告”当作提取完整的保证。

## 怎么操作

1. 选择具体文件修订。新版和旧版分开核对，不能混用。
2. 看摘要：规则警示页数、人工已核对页数，以及人工标记需处理的页数。程序规则和人工决定分别统计。
3. 选择页面，阅读提取文字，点击“打开本页原件”回看对应 PDF。浏览器支持 PDF 页锚点时定位到该页；不支持时按原件页序手动翻页。
4. 明确选择本次核对结果，填写说明并保存：

| 结果 | 何时使用 |
|---|---|
| 已回看原件，文字可用 | 本页有提取文字，人工认为可以继续使用；仍不是机器保证无遗漏 |
| 需要重新处理 | 原件有内容但提取为空、存在乱码、读乱或明显缺失，记录具体原因 |
| 已确认原件这一页为空白 | 本页没有提取文字，且人工确认原件本身确实为空白；不能用于有提取文字的页 |

5. 使用“只看规则提醒或待处理页”定位需关注的页面。可查看本页最近50条核对历史；接口支持继续分页。

只有负责人、编写人、审查人可以追加记录；只读成员可以查看。每次保存都是新记录，包含实际账号、说明及递增版本。另一人先提交时返回冲突并要求刷新，不能静默覆盖。

## 程序能提示什么

| 提示 | 规则 | 应怎样理解 |
|---|---|---|
| 没有可提取文字 | 本页没有文字块 | 可能是真空白、图片/扫描页或提取失败；规则不能判断原因 |
| 文字量较少 | 少于30个非空白字符 | 低等级提醒，封面和分隔页也可能正常 |
| 疑似字形映射异常 | 含替代字符或未映射 CID 标记 | 回看对应原文，考虑重新导出字体映射正确的 PDF |
| 坐标异常 | 文字矩形无效或超出页面边界，允许1point误差 | 引用位置可能不可靠，需看原件 |
| 文字块大幅重叠 | 空间相邻块重叠面积达到较小块的80% | 可能有重复文字层；不能据此认定表格或多栏正确/错误 |

每条规则给出中文建议，并最多标出20个相关文字块。大量文字按每组100处翻组阅读。

## 与审查结果的关系

解析质量核对和“投标响应满足招标要求”是两件事。保存质量意见不会发布基线、替换正式材料、增加业务输入版本，也不会直接改变当前业务报告。0.5.0 尚未将页级意见设为业务操作的强制门槛。

若发现有内容却没读出来，当前做法是提供带文字层的 PDF、重新上传修订，再核对新产物。尚未提供一键 OCR、Docling、表格重建或自动重解析。新修订和新解析产物的人工记录从零开始，旧记录继续可查。

## 可复现的提取检查点评测

仓库提供4份同一构造模板的 PDF 和6个指定页码/短句检查点。运行：

```powershell
docker compose exec -T api python scripts/evaluate_extraction.py
```

输出默认保存在容器的 `data/evaluation/extraction-report.json`，排除在 Git 和源码包之外。控制台只输出摘要；报告不复制检查点原文，保留来源摘要、页数及命中结果。任一已标注检查点未命中或页数不符时以非零状态退出。

可按 `evaluation/extraction/manifest.json` 的结构提供自己的清单，通过 `--manifest` 和 `--output` 指定路径。私人文件与清单应放在本地受控目录，不提交到仓库。

命中率只表示已标注短句在指定页出现，不能评价未标注的漏字、完整要求覆盖率、表格语义、扫描件 OCR 或模型业务准确率。当前数据集只有一种模板家族，还需要扩展不同真实模板的完整人工标注。
