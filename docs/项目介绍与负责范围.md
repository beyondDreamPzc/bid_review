# 项目介绍与负责范围

## 简短介绍

这个项目解决投标材料审查中三个问题：要求分散在多份招标文件里，响应证据难定位，多人整改后很难确认审核结论对应哪一版文件。我负责核心后端、文档处理和证据检索链路，用FastAPI提供业务接口，MinerU解析PDF，MySQL保存文件版本、要求基线和审核事实，Redis/Celery处理异步任务，Milvus对当前正式材料做中文BM25检索。

基本流程是上传和检查原文、整理并确认要求、发布要求基线与正式材料、搜索响应证据、登记问题并整改、由另一人复核，最后形成可追溯报告。可选模型只生成要求候选，人工采纳后仍需要确认。

实现中重点处理两个问题。一是任务重投和Worker超时，通过幂等键、MySQL事务outbox、执行租约和代次隔离，避免重复操作及旧任务回写。二是材料更新后引用和结论错配，通过不可变修订、冻结材料集、审查版本及索引版本隔离，让历史可追溯，让当前审核明确采用哪一版。

## 技术与负责内容对应

|工作|当前实现|
|---|---|
|业务后端|FastAPI/Pydantic，项目角色、Cookie会话、中文OpenAPI、幂等和审计|
|版本与并发|SQLAlchemy/MySQL/Alembic，项目行锁，输入版本检查，要求与材料不可变快照|
|文档处理|独立MinerU4.0.12运行环境，文字/扫描PDF，源文件摘要、实际页码和坐标，人工逐页质量意见|
|可靠异步|Redis/Celery分离parse/extract/retrieve队列，MySQL任务与outbox，续租、有限重试、过期恢复和旧Worker拦截|
|证据检索|Milvus2.6.6中文分词/BM25稀疏向量，冻结chunk出处、索引代次发布、服务端权限及版本过滤、MySQL原文校验|
|人机协同|可选云模型结构化要求候选，输入确认、结果校验、人工编辑采纳；整改提交者不能复核自己|
|前端与交付|HTML/CSS/JavaScript响应式工作台，Docker Compose，55个已注释接口，75项回归和真实依赖集成验收|

没有加入当前流程不需要的LangChain/LangGraph依赖。稠密语义检索、混合召回与重排、生成式RAG回答、模型合规比对尚未实现，不能作为已完成的职责来讲。真实云模型效果与多模板业务准确率尚无实测数字；当前可引用的验收证据见[检索验收](retrieval-verification.md)、[MinerU验收](mineru-verification.md)与[候选链路验收](extraction-verification.md)。
