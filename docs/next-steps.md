# 后续开发顺序

## 当前交付边界

0.7.0已将新上传/重解析接到本地MinerU4.0.12 Flash/auto，完成文字PDF与构造扫描页的真实SDK验收，保留历史引用及质量记录隔离。0.6.0要求候选与人工闭环继续可用；云模型语义效果未验证，RAG/Milvus和自动合规审查仍未实现。

## 下一次优先交付

1. 在本地配置选定模型，用明确许可发送的样本验证实际兼容性和条款覆盖。补至少三个不同模板项目的完整人工标注，评估遗漏、错误拆分、条件保留、引用和人工采纳率；不能把结构校验通过率当作语义准确率。
2. 建立 Milvus 检索投影，冻结文件版本、索引profile与chunk来源；先让人查询和回看本轮正式材料，再做混合召回及reranker。MySQL继续保存事实和人工审核快照。
3. 扩展MinerU多模板、混合文字/图像和复杂表格验收，评估Basic档位；使用新profile保留历史。固定 LibreOffice/字体，加入 DOCX 的不可变 PDF 渲染链。
4. 扩展多模板解析评测与错误标注；当前质量规则只能发现部分可疑页，不能证明整文完整。
5. 多步骤响应检查确有编排需要时再引入 LangGraph。目前候选抽取使用明确的Python状态机，未安装LangGraph。
6. 逐项响应检查仅生成带来源的疑似问题，置信不足转人工；不自动关闭整改或代替最终决定。
7. 加入更正条款关联和局部影响评估，逐步替代当前整项目失效的保守策略。

以上后续检索、模型审查和新解析能力尚未实现。另需补任务转派、问题撤销、要求退休/删除、批量分页/筛选、组织身份与 API Key 生命周期、通知和备份恢复；Markdown 报告导出已完成，其他格式未提供。当前已有任务负责人须保留 EDITOR 权限。
