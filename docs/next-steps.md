# 后续开发顺序

## 当前交付边界

0.5.0 在真实账号网页人工闭环之外，新增逐页质量规则、人工核对历史，以及4份同模板构造 PDF 的6个页码/短句检查点。原有构造样例演示保留。诊断产物有原件 hash、页码、bbox 和文本 hash；质量检查不重写旧来源，人工引用须回看原件。当前 HUMAN，尚无模型自动抽取、RAG/Milvus 或自动合规审查。

## 下一次优先交付

1. 逐页质量核对和检查点评测框架已提供。继续扩展不同模板的完整人工标注；当前只有同模板构造数据，不能据此声称多模板效果或整文准确率。
2. 加入固定 Docling adapter 验证段落、表格与 OCR；保留新 profile。固定 LibreOffice/字体，加入 DOCX 的不可变 PDF 渲染链。
3. 标注至少三个不同模板项目的要求、响应和问题，评估来源定位、要求覆盖、误报与漏报。
4. 接入可替换云模型 API，由 LangGraph 组织候选要求抽取、结构校验、人工确认；模型不得直接发布基线。
5. 建立 Milvus 检索投影、混合召回和 reranker；MySQL 继续保存事实、版本与人工审核快照。
6. 逐项响应检查仅生成带来源的疑似问题，置信不足转人工；不自动关闭整改或代替最终决定。
7. 加入更正条款关联和局部影响评估，逐步替代当前整项目失效的保守策略。

以上后续模型/解析能力尚未实现。另需补任务转派、问题撤销、要求退休/删除、批量分页/筛选、组织身份与 API Key 生命周期、通知和备份恢复；Markdown 报告导出已完成，其他格式未提供。当前已有任务负责人须保留 EDITOR 权限。
