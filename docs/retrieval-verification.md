# 0.8.0正式材料检索与界面适配验收

日期：2026-10-21。Windows本机Docker Desktop Linux容器，MySQL8.4、Redis7.4、MinerU4.0.12、Milvus2.6.6。全部业务材料为仓库构造PDF，不是客户数据。

## 验收结果

运行`pytest tests -q`：75 passed，含新增11项检索用例。保留已有Starlette/httpx测试客户端弃用警告。Alembic升级至0007，`alembic check`无新增操作；OpenAPI共55个操作，包含3个新检索接口。

真实验收：`docker compose exec -T api python -m scripts.retrieval_smoke`。脚本只使用仓库PDF，通过HTTP上传、真实MinerU解析、MySQL/outbox、Redis/Celery及真实Milvus完成：

|检查|实际结果|
|---|---|
|4路相同幂等请求构建|同一索引、同一任务|
|中文查询“响应时限”|旧正式响应命中4小时，附带实际页码|
|参考材料排除|结果只来自FORMAL_RESPONSE，REFERENCE未入索引|
|仅上传2小时新版|查询仍按已发布4小时材料|
|发布2小时材料|旧材料ID查询409，新材料未建索引也409|
|新索引|23个片段，命中2小时，不含旧4小时文本|
|片段引用核对|每条命中与来源接口的字符切片一致|
|随机不存在词项|空数组，无合成答案|
|明确重建|成功后恢复查询，来源仍绑定原产物|
|停止真实Milvus|检索503，API健康及其他业务仍可用|
|重启真实Milvus|无需重建即可200，持久化索引恢复|

单元测试另外验证：读者不能构建、外项目404、输入变更409、空查询422、服务关闭503；网络查询期间移除成员/换材料/重建会拒绝结果；外部伪造片段和篡改正文503；过期租约不能发布半成品；任务失败不会污染PDF状态；明确重试/重建使用新代次；字符窗口和重叠准确；错误信息不透出远端正文和连接细节。单元测试使用投影替身测试故障分支，以上真实验收使用实际Milvus，没有以替身代替真实检索结果。

## 界面验收

工作台默认15px正文，原文14px、输入控件在窄窗口16px；容器上限由1240增加到1600，宽屏侧边步骤栏、中等窗口横向导航、640px以下步骤下拉。资料列表的上传表单可展开，已上传项目不再默认展示整张上传表单。长解析配置、文件名和引用允许换行；材料选择单列排列，表单按钮保留点击高度。

通过真实浏览器登录测试账号，完成步骤下拉→构建索引→中文查询→原件页码链接→将原文带入本轮审查。第1项命中响应第2页，选中引用显示1/20且文本与原文一致。当前371px视口的资料页和审查页document.scrollWidth为356px，没有横向溢出；正文15px，控制台无脚本错误。

浏览器截图接口在本轮返回“Unable to capture screenshot”，所以没有将旧版图片冒充新界面截图。宽屏与中等断点已实现，但本轮仅有371px实际浏览器尺寸的验证记录，没有多尺寸截图或真实设备验收。其余断点仍需在相应窗口进行视觉复核。

## 仍未验证的能力

本次不是检索召回率评测，也没有稠密向量、混合召回、reranker、真实云模型推理、线上并发性能或可用率数据。23个片段和4路幂等请求仅是此构造样本的规模与功能验收，不能用于宣称生产容量。
