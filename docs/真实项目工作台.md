# 真实项目工作台使用说明

适用版本：0.4.0。入口：http://127.0.0.1:18080/workspace 。原有 http://127.0.0.1:18080/ 继续用于构造样例演示。

这里的“真实项目”表示文件、要求和操作身份由使用者自行提供，不再限定预设样例；不表示已经在企业生产使用。当前全部判断由人完成。

## 第一次进入

启动 Compose 后，在项目目录中打开本地 `.env`，把 `BID_BOOTSTRAP_API_KEY` 的值填入网页的“账号访问密钥”。这是初始负责人账号的凭据，不要复制到文档、Git 或聊天中。登录后网页只使用七天有效的 HttpOnly 会话 Cookie；退出会在服务器撤销当前会话。不同电脑的其他会话不受影响。

创建项目，例如“某平台运维投标”。项目资料、要求、问题和报告按成员权限隔离；没有成员权限的账号不能访问原件或项目工作台。

## 01 资料与版本：把双方文件放进来

先上传采购方的招标 PDF，资料类型选“招标文件”；更正公告选“更正文件”。再上传我方的投标 PDF，选“投标响应”；资质和案例等附件选“证明材料”。

等待“解析完成”，打开原 PDF 检查页码和提取文字。当前只支持有文字层的 PDF，最大 50 MiB、300 页。扫描件没有 OCR，复杂表格可能出现顺序或内容不完整；解析成功不等于质量已确认。

右侧明确选择响应文件的某一版及用途。“正式响应”至少一份；“正式附件”可以作为证明；“仅供参考”不能用于确认正式响应满足要求。点击发布后，这些版本固定为本轮材料。上传新版不会自动替换正在核对的文件。

**修改文件的方式**：在“保存为”选择已有文档的“上传新版”，再选择修改好的 PDF。不要为了修改内容而重复新建逻辑文档。旧版始终保留；上传相同字节会复用已有修订。

## 02 整理要求：把招标原文拆成可核对条目

选择招标文件及页码，勾选有关文字，例如“故障响应不得超过2小时”。可以跨文件、跨页选择，单次最多20处引用；页内超过100处文字时可继续翻组。出处由服务端回查并冻结，不能在输入框里伪造原文。

填写标题、完整要求、类别和重要性。保留适用范围和例外条件，不要凭空推断必须满足项。保存后状态是“待确认”。负责人或审查人核对原件，再点击“核对原文后确认”。所有条目确认后，发布全部要求。

确认表示“录入正确”；发布表示“这轮按这份清单检查”。这两步都不表示我方已经满足要求。

“修订要求”创建新草稿，保留旧版本。新稿确认并重新发布之前，审查页面仍展示旧基线；报告提示有未发布变化，不能显示整个项目已完成。首版尚不支持要求删除或退休。

## 03 本轮审查：逐条做有依据的人工判断

左侧是基线冻结的要求及出处；右侧选择当前正式材料的页码和原文。

- 人工确认满足：选择响应证据，填写核对意见，保存。
- 不适用：说明本项目为什么不适用；有未解决问题时不能直接跳过。
- 有问题：展开问题登记，写清缺口、类型、优先级、负责人和可选期限，使用上方选择的正式响应证据。承诺冲突必须有响应原文；缺少响应或证明时可不引用，但应说明检查范围。

登记问题会创建整改任务，也会让此前的满足决定失效。需要时再保存“确认有问题”的审核记录。当前没有 AI 自动抽取、自动判定或自动生成整改文件。

## 04 整改复核：真实账号交接

只有任务负责人可以开始或提交整改。负责人先开始整改，在自己的文档编辑工具中修改 PDF 对应的源文件，再上传 PDF 新版并发布更新后的正式材料集。

回到整改任务，选择当前正式材料中的修改后原文，填写修改说明，提交。另一位负责人或审查人登录，打开提交证据与原件，填写意见并验收或退回。提交人不能复核自己的提交，页面没有“切换演示角色”入口。

验收解决的是具体问题；仍须回到本轮审查，对该要求作最终人工判断。新增材料集或要求基线后，旧提交和验收显示需要重新核对，任务负责人可重新开始并提交。

## 成员与账号

负责人在“成员”输入至少两个姓名字符，查找管理员已经创建的账号，再加入为编写人、审查人或只读成员。搜索结果不包含演示人物，不显示访问密钥。

当前没有网页注册或密码找回。管理员可在 PowerShell 用已有 CLI 创建账号，以下从交互输入读取新密钥，并通过进程环境传入容器；不把密钥写进命令参数或仓库：

```powershell
$bidTeamSecret = Read-Host '输入至少24字符的随机访问密钥' -AsSecureString
$env:BID_TEAM_API_KEY = [System.Net.NetworkCredential]::new('', $bidTeamSecret).Password
docker compose exec -T -e BID_TEAM_API_KEY api python -m app.cli bootstrap --name '李工' --key-env BID_TEAM_API_KEY
Remove-Item Env:BID_TEAM_API_KEY
$bidTeamSecret.Dispose()
```

把此账号密钥通过自己的可信渠道交给对应使用者，不要提交到 Git。浏览器输入已有密钥只是登录，不创建另一个身份。单人体验可先完成无问题项目的逐项审查；需要验收整改时必须有另一个实际账号。

## 05 检查报告

报告分别显示当前基线要求数、已人工确认数和未解决问题数。只有本轮全部要求有有效的满足/不适用决定、无未解决问题、无未发布要求变化时，才显示“本轮人工核对完成”。

Markdown 下载包含生成时间、材料版本与原件摘要、要求出处、人工意见及问题整改记录。下载的是当时快照，后续项目仍可修改；不是自动合规结论。服务器仍保留完整版本和提交历史。

## 当前限制与下一步

工作台适合小规模本地人工流程，聚合读取暂未分页，不适合直接用大量文档压测推断性能。暂不支持网页账号管理、任务转派、问题撤销、要求删除、DOCX、扫描件 OCR、RAG/Milvus 和模型判断。共享部署前还需 HTTPS、组织身份、会话和密钥生命周期、上传配额及备份恢复。

下一步先改进解析质量与评测数据，再接可替换模型做“要求候选抽取→人工确认”；模型不能直接发布要求基线或验收整改。
