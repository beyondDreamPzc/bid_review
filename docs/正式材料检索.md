# 正式材料证据检索

> 版本说明：本文正文保留0.8及以前的实现记录。1.0已新增混合检索/重排、DOCX和辅助检查等，当前状态与限制以[1.0交付说明](版本1.0交付记录.md)及[完整启动与运维](完整启动与运维.md)为准；新增能力尚待运行验收。

适用0.8.0。解决的业务问题是：面对一条招标要求，审查人需要知道响应书或证明附件“究竟在哪一页承诺了什么”，并确保查到的是本轮正式提交的版本。

## 使用流程

1. 上传响应PDF，等待MinerU解析，回看原件和解析质量。
2. 在“资料与版本”选定响应/附件的修订及解析产物，发布正式材料集。
3. 进入“证据检索”，点击“构建本轮索引”。排队和构建在后台执行，完成后显示可检索及片段数。
4. 查询“响应时限”“培训次数”等关键词，查看原文及实际PDF页码，点击原件回看。
5. 已有要求基线时，可以点击“用于本轮核对”。系统将完整原文块带入当前选中的要求，人工决定是否采用；切换要求会清空引用。

只有OWNER/EDITOR可以构建，所有项目成员可以搜索。REFERENCE材料不入库；上传新版不会自动改检索依据，发布新材料集后旧索引不再用于当前查询，必须为新材料构建索引。重解析同样不替换已发布材料采用的产物。

## 接口对应哪个业务需求

|接口|业务触发|结果及下一步|
|---|---|---|
|GET `/api/v1/projects/{project_id}/retrieval`|进入检索页或轮询进度|当前第几套材料、任务状态、片段数量；不代表Milvus当前在线|
|POST `/api/v1/projects/{project_id}/retrieval/indexes`|负责人明确构建/失败重试/成功重建|202及job_id，随后轮询；相同材料/profile只有一条索引事实|
|POST `/api/v1/projects/{project_id}/retrieval/search`|审查人输入关键词寻找响应原文|原文片段、文件修订、解析产物、页码、整块坐标和原件地址；无命中返回空数组|

写索引时带Idempotency-Key；查询是无副作用的POST，不需要幂等键。全部字段、错误和中文注释由代码导出到[接口手册](API接口说明.md)，以Swagger为准。

## 为什么这样实现

MySQL保存`RetrievalIndex`和`RetrievalChunk`事实，Milvus是可重建的检索投影，不保存人工审核决定。材料集和解析产物不可变，每个原文块以1200个Python字符为窗口、120字符重叠拆分；不跨页或跨块拼接。保留原始大小写、数字和措辞。每片段保存原件/产物/整块摘要、字符起止、实际页码和整块bbox。长表格可能被切成多个片段，不能据此声称恢复了表格单元格语义。

采用Milvus2.6.6的中文分词器和内建BM25函数，生成稀疏向量，通过SPARSE_INVERTED_INDEX检索。这个阶段是词项相关性检索，没有稠密语义embedding、混合召回、reranker或生成式问答。分数不是概率，不作为自动合规判断。

构建任务使用MySQL/outbox、Redis/Celery独立retrieve队列，分批100片段写入。每次尝试使用`index_id:lease_token`代次；网络写在事务外，每批前后续租。只有全部写完且租约有效才发布MySQL的published_token。旧Worker即使晚到写入Milvus，也无法被当前检索选中。失败有限自动重试；超限由负责人明确重试；重建期间该索引不可检索。

每次查询由服务端选择项目与已发布代次过滤，用户不能传Milvus表达式或指定其他项目索引。网络查询后重新检查成员权限、材料集和代次；再用MySQL片段ID取回原文，校验块摘要及字符切片。索引返回外项目片段、篡改原文或查询期间变更输入时整次拒绝，不把外部索引正文直接当证据。

## 部署与恢复

Compose增加独立retrieval-worker及一个真实Milvus Standalone容器，使用官方embedded-etcd/local-storage部署模式；不是Milvus Lite，也不是分布式集群。镜像固定版本及摘要，`milvus_data`命名卷持久化元数据、日志与索引。没有宿主机端口映射，只在项目内部网络通信；API仍绑定127.0.0.1。云模型密钥不传入retrieval-worker，检索不向云模型发送正文。

采用[官方Standalone嵌入式部署脚本](https://github.com/milvus-io/milvus/blob/v2.6.6/scripts/standalone_embed.sh)的配置模式。[BM25文档](https://milvus.io/docs/full-text-search.md)与[中文分词文档](https://milvus.io/docs/chinese-analyzer.md)说明算法和分词行为。本机MinIO官方历史镜像拉取失败，因此使用官方单容器存储模式，没有引入来路不明的替代镜像，也未修改用户Docker镜像源。

Milvus不可用时查询返回503，其他资料、人工核对与报告接口仍可工作。MySQL索引状态是构建事实，不是在线健康检查。Milvus普通重启后索引可继续查询；投影丢失时用“重建索引”重放MySQL冻结片段。重建不改变要求基线、epoch或人工意见。

当前每套材料最多10000片段，查询最多500字符、10个不同原文块。尚未做全量容量/延迟基准；失败尝试与历史材料的投影暂保留，尚无自动清理策略。共享生产部署仍需独立认证、TLS、资源配额、监控、备份恢复演练及保留策略。不能把本机故障恢复测试描述为生产高可用验收。
